# 🤖 AI Data Architect: Интеллектуальная Система Оптимизации Data Lakehouse

*Прототип интеллектуального сервиса для автоматической оптимизации производительности Data Lakehouse-систем на базе Trino и Iceberg.*

## 🚀 Наша Философия: "Крепкий Завод", а не "Хрустальный Дворец"

Вместо того чтобы создавать хрупкое решение на основе самых "хайповых" технологий, мы построили **стабильный и надежный инженерный фреймворк**. Наша система — это не "черный ящик", а **объяснимый AI-ассистент**, который имитирует рабочий процесс команды опытных дата-архитекторов.

**Ключевые ценности нашего подхода:**
*   **Объяснимый ИИ:** Мы не просто получаем результат, мы понимаем, почему он такой.
*   **Гибкая Архитектура:** Систему легко расширять для поиска новых типов проблем.
*   **Надежные Ограничители (Guardrails):** Мы не доверяем LLM вслепую — мы проверяем каждое ее предложение.
*   **Прагматичный RAG:** Мы используем "Диспетчер Паттернов" — детерминированный аналог RAG, который гарантирует предсказуемость.

## 🏛️ Архитектура Решения

Наша система — это многокомпонентный конвейер, где каждый блок выполняет свою четкую задачу, сочетая мощь классического анализа и генеративных моделей.

  *(Здесь будет ссылка на диаграмму нашей архитектуры)*

1.  **API-Сервер (FastAPI):** Принимает асинхронные задачи на оптимизацию.
2.  **Аналитический Модуль (DE-ядро):**
    *   **Профилировщик:** Собирает "анамнез" — `EXPLAIN`-планы и метаданные для всего пула запросов.
    *   **"Библиотека Детекторов":** Наш главный инновационный компонент. Набор независимых "экспертов", каждый из которых ищет свою специфическую проблему:
        *   `JoinPatternDetector` (ищет симптомы Data Vault)
        *   `PartitioningCandidateDetector` (ищет непартиционированные "горячие" таблицы)
        *   `CrossJoinDetector` (находит самые опасные операции)
        *   `InefficientAggregationDetector` (обнаруживает неоптимальную фильтрацию)
        *   `SelectStarDetector` (борется с избыточным чтением данных)
    *   **Приоритизатор:** Оценивает экономическую "стоимость" каждой проблемы и выбирает самую важную.
3.  **Интеллектуальный Агент (ML-ядро):**
    *   Получает диагноз от Аналитического Модуля.
    *   С помощью **Диспетчера Паттернов** выбирает идеальный, заранее написанный "золотой шаблон" решения.
    *   Формирует "мега-промпт", давая LLM четкую задачу: "Не думай с нуля, а адаптируй вот этот эталонный пример под текущий контекст".
4.  **LLM-Провайдер (Гибкий Бэкенд):**
    *   Абстракция, позволяющая легко переключаться между мощными облачными API (Gemma) и **локально развернутыми, специализированными моделями**, обеспечивая гибкость и независимость.
5.  **Валидатор (Наш "Guardrail"):**
    *   Получает сгенерированный LLM код.
    *   Использует "хитрый" трюк с **симуляцией через CTE**, чтобы проверить семантическую корректность всего решения (DDL + миграция + запросы) **без прав на запись** в основную базу.
    *   Если валидация проваливается, Агент запускает **цикл самоисправления**, объясняя LLM ее ошибку.

## ✨ Ключевые Преимущества

*   **Стратегический Подход:** Мы не оптимизируем запросы поодиночке. Мы находим **глобальную архитектурную проблему** и решаем ее, что дает максимальный выигрыш.
*   **Расширяемость:** Чтобы "научить" систему находить новые проблемы (например, `Z-Ordering`), достаточно добавить один новый класс-детектор. Ядро системы останется неизменным.
*   **Надежность:** Встроенный цикл валидации и самоисправления гарантирует, что на выходе мы получаем **проверенный, рабочий код**.
*   **Гибкость LLM:** Наша архитектура с абстрактным провайдером позволяет выбрать лучший инструмент для задачи: от мощнейшей облачной модели до легковесного, но узкоспециализированного локального сервера.

## 🚀 Как Запустить

### Локальная Разработка (с локальной LLM через Llama.cpp)

Идеально для быстрой разработки, тестирования и работы без зависимости от облачных API. Использует модель **`gemma-3-27b-it-q4_0.gguf`**, запущенную на высокопроизводительном сервере `Llama.cpp` с поддержкой GPU-ускорения (например NVIDIA L4).

1.  **Установите Docker и NVIDIA Container Toolkit.** Убедитесь, что драйверы NVIDIA обновлены.
2.  **Скачайте модель:** Поместите файл модели `gemma-3-27b-it-q4_0.gguf` в директорию `models` в корне вашего проекта.
3.  **Запустите Docker Compose:**
    ```bash
    docker-compose -f docker-compose.local.yml up --build
    ```
    *При первом запуске Docker скачает образ `llama.cpp` (~2 ГБ). Серверу модели может потребоваться 1-2 минуты для полной загрузки и готовности к приему запросов (следите за логами в консоли).*
4.  **API будет доступен по адресу:** `http://localhost:8000/docs`.

### "Облачное" Развертывание (с Gemma API)

Идеально для production. Требует минимальных ресурсов (см. анализ ниже).

1.  **Создайте `.env` файл** и укажите в нем `GEMMA_API_KEY`.
2.  **Запустите Docker Compose:**
    ```bash
    docker-compose up --build
    ```
3.  **API будет доступен по адресу:** `http://localhost:8000/docs`.
